fix(hr): 生产链路频带非法时不再回退写入带外伪值

⚠ 本次改动位于 🔒 锁定区块 B 内, 依据用户明确授权:
  「我明确授权你可以根据工程需要修改锁定区」
锁定区块 A (compute_hr_with_tracking) 未改动, 注入脚本已断言逐字节一致。

## 现象

🔒生产链 current_hr_numeric 有 9.5% 的样本落在 60bpm 以下,
实测集中在 43.8~46.7 这个很窄的区间。

## 根因(逐条日志验证, 非推测)

1. new_hr=nan 占 8.91% (337/3783)。
2. 这些 nan 全部发生在 effective_fs 塌到 ~1.8 的时刻:
   nan 样本 fs 中位数 1.82(全部<2.2); 正常样本 fs 中位数 30.0。
3. 产生 nan 的代码本身是对的 —— line~1102 判断
   `if new_safe_ul_pr > HR_TRACK_LL_PR:` 否则返回 nan。
   fs=1.8 时 safe_ul = 1.8*60/2*0.9 = 49.2 < LL_PR=58, 频带非法。
   实测 96.8% 的 nan 样本满足 fs <= 2*LL/60, 机制吻合。
4. 问题在【回退】: 此时改用 calculated_hr, 而它是在【同一段退化信号】上
   用 LL_PR=40 算出来的。fs=1.8 的奈奎斯特上限只有 54.7bpm, 候选频带
   被压成 40~49bpm 的窄条, 输出必然落在其中。
   实测回退值范围 [40.0, 46.7], 与理论窄带完全吻合
   —— 这不是心率, 是频带边界伪影。
5. 低帧率本身的成因也已定位, 且不在计算侧:
   坏窗口 100% 伴随 SHADOW-GATE 帧饥饿拦截(好窗口仅 33.1%),
   即浏览器页面切后台/关闭后停止上传帧。

## 修复

频带非法(new_safe_ul_pr <= HR_TRACK_LL_PR)时【本轮不写入】, 沿用上次
有效值 —— 与影子链路 SHADOW-GATE 已采用的 freeze-on-failure 语义一致。
频带合法但选峰失败导致的 nan 仍按原逻辑回退到 calculated_hr, 行为不变。

加固: new_safe_ul_pr 定义在上游 try 内, 若该 try 在赋值前抛异常, 直接引用
会 NameError 并击穿整个 rppg_processing_loop。改用 locals().get() 兜底,
取不到时按"频带未知"处理 => 保持原有回退行为, 不引入新的失败模式。

可观测: [NEW-HR-DEBUG] 增加 band_invalid= 与 band_skips= 两个字段。

  现状(总是回退)      n=3891 mean=81.70 <60占 9.5%  in[60,100]=78.3%
  本修复(非法则冻结)  n=3540 mean=85.46 <60占 0.6%  in[60,100]=86.1%
  代价: 9.0% 的轮次不更新 —— 这些轮次本就不含有效信息

py_compile 通过; 🔒锁定区A 逐字节一致(3516字符); 重启后 HTTP 200、
模型加载正常、无异常堆栈。线上稳态复核待有真实会话后补充。

## 范围说明(避免误读)

生产链路当前【不对用户可见】: /max 前端只读 heart_rate 字段, 该字段来源是
影子链路(primary_hr_display_val)。本修复改善的是 legacy_production_heart_rate
与 hr_history_buffer 的数据质量, 不改变 /max 的显示。

## 局限(必须诚实说明)

这仍然不是精度提升。实测采集帧脉搏信噪比约 1:1, 心率绝对准确度至今未被
验证过 —— 需要一次真正同步的 ECG + 系统同时段测量。此前对照的 ECG 报告
(78.3)与采集时间窗完全不重叠, 不能作为准确度证据。
