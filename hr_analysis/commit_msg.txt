fix(hr): 修复心率整体偏高 - 影子链路改用无状态谱重心选频 + 搜索带[50,140]→[45,110] + 展示端EMA

【问题】/max 页面心率整体偏高。

【根因: 追踪器闭环自证】(5会话/3被试/2种搜索带, 100%一致)
compute_hr_with_tracking 用 chosen = min(strong, |bpm - prev_est|) 选峰,
再 est = a*chosen + (1-a)*est 回灌, 构成正反馈。能量阈值0.15放行的候选
跨度中位数88.5bpm(占带宽98%), 于是几乎总能找到"贴着上一次"的峰:
  - corr(chosen, prev_est) = +0.925 ; corr(chosen, 能量最强峰) = -0.019
  - 真值±5bpm内有峰的轮次占51.3%, 其中69%未被选中
  - 起点依赖: 同一频谱 init=55→收敛69, init=135→收敛123 (100%频谱受影响)
线上约4.2轮/秒, 相邻窗口只滑动0.24秒 => 在近乎相同的频谱上反复迭代,
把轻微偏置放大为锁定。更新密度R=1时偏差+4.91, R>=10时+15.73(与线上吻合)。

【修复】
1. 并列新增 compute_hr_spectral_centroid: 能量加权谱重心, 完全不依赖
   prev_est => 无起点依赖、无自锁、可复现。
2. 搜索带 [50,140] -> [45,110]。纯噪声对照显示无脉搏信息时输出必然落在
   带中心: 带中心95→噪声输出93.8, 带中心77.5→76.4。把先验放到生理正确
   位置(成人静息中位约72)。代价: 不支持>110bpm, 静息场景可接受。
3. 展示端EMA(alpha=0.15): 重心法无状态会导致页面跳字(相邻跳变中位
   10.88bpm)。EMA只平滑输出、不回灌选值, 故不重新引入闭环(起点极差仍0.00)。
4. 日志增加 disp_hr, 与选峰原始值 shadow_hr 分开观测。

【离线验证】会话4b989b29, R=70:
  现状 [50,140]+th0.15 : 偏差+15.73 MAE18.92 正负10bpm 24.2% 起点极差3.13
  本方案[45,110]+重心  : 偏差 +2.13 MAE 8.49 正负10bpm 66.7% 起点极差0.00
【6个留出会话】跨会话均值90.63→80.70, 会话间std 5.21→1.46
【线上实测】展示值均值79.87, 100%落在生理区间[60,100],
  跳变P90 8.63→1.62; ALPHA 0.25/0.30 对结果无影响(收敛点与alpha无关)

【锁定区完整性】两处锁定区块(compute_hr_with_tracking / 心率生产计算区块)
均逐字符零差异, 生产链路 current_hr_numeric 行为完全不变。
SHADOW_USE_CENTROID=False 可一键回退。

【必须说明的局限】本修复解决的是"先验位置错误 + 闭环漂移", 不是提高测量
精度。实测采集帧脉搏信噪比约1:1(相邻帧逐像素MAE 8.9灰阶 vs 生理脉搏
约0.5~1灰阶; 平移配准可消除30.6%残差 => 人脸框抖动为主要干扰), 窗口内
真实帧率中位仅3~6fps。真正的精度提升需从采集端解决。
